# BM25 关键词检索打分

本文档说明 BM25 是什么、为什么用它，以及 NexusAI 知识检索中如何落地。BM25 是**字面关键词相关性**打分，和 pgvector 的**余弦距离（语义相似）**互补，二者融合后作为 `search_knowledge` 的重排序信号。

## 1. 要解决的问题

向量检索按余弦距离召回最相似的若干分块，但它对**精确字面词**不敏感：一个分块反复出现查询里的罕见关键词，可能因向量方向略有偏差而排得靠后。BM25 补上这个短板——只比对词的字面命中，回答「用户搜的这些词，这个分块有多相关」。

它来自信息检索领域的 Okapi BM25，是纯规则、无外部依赖的确定性打分，符合本项目「重排序不引入交叉编码器等外部依赖」的约束。

## 2. 三个核心思想

BM25 由三个想法叠加而成，各自解决一个问题：

| 想法 | 解决的问题 | 直觉 |
| --- | --- | --- |
| 词频 tf | 一个词出现次数越多越相关 | 出现 10 次 ≠ 出现 1 次的 10 倍重要，需要「饱和」 |
| 逆文档频率 idf | 越罕见的词越有区分度 | 「的」「是」命中再多也没信息量，「蓝雀」命中才说明真相关 |
| 长度归一化 | 长文档天然更容易命中 | 不能因为文档长就占便宜，要打折 |

### 2.1 词频 tf（Term Frequency）

```
tf × (k1 + 1)
─────────────
tf + …
```

`k1` 控制饱和速度。tf 从 1 → 2 时涨得快，从 9 → 10 时几乎不再涨。

### 2.2 逆文档频率 idf（Inverse Document Frequency）

```
idf(t) = ln( 1 + (N − df(t) + 0.5) / (df(t) + 0.5) )
```

- `N`：候选池中的分块总数。
- `df(t)`：候选池中包含词元 `t` 的分块数。

`df` 越小（词越罕见），`idf` 越大。当 `df = N`（所有分块都含这个词）时 idf 接近 0，即「到处都有」的词几乎不加分。

### 2.3 长度归一化（Length Normalization）

```
k1 × (1 − b + b × |D| / avgdl)
```

- `|D|`：当前分块的词元数。
- `avgdl`：候选池平均词元数。
- `b` 控制打折力度，`b=0` 完全不按长度打折，`b=1` 全额打折。

## 3. 公式与参数

对查询里的每个词元求和：

```
score(Q, D) = Σ  idf(t) ×  tf(t,D) × (k1 + 1)
               ─────────────────────────────────────────
               tf(t,D) + k1 × (1 − b + b × |D|/avgdl)
```

NexusAI 采用的参数为业界常用默认值：

| 参数 | 值 | 含义 |
| --- | --- | --- |
| `bm25K1` | 1.2 | 词频饱和速度 |
| `bm25B` | 0.75 | 长度归一化力度 |

## 4. NexusAI 的落地选择

实现位于 `services/api/internal/knowledge/rerank.go` 的 `bm25Scores`，有三个与标准 BM25 不同的取舍：

### 4.1 词元用 bigram

中文没有空格分词，引入分词器又太重。NexusAI 用 **bigram**（相邻两个有意义字符）作词元：`蓝雀告警` → `蓝雀`、`雀告`、`告警`。规则与 `factcheck.go` 的 `significantBigrams` 一致——跨中英文的相邻字不成对，所以 `API服务` 得到 `AP`、`PI`、`服务`，不会出现 `I服`。

bigram 比单字符更能表达中文词义（`告警` 是一个词，拆成 `告`、`警` 会丢失搭配信息），又避免依赖分词库。

### 4.2 局部 BM25（候选池内统计）

标准 BM25 的 `df`、`avgdl` 要在**整个语料库**上统计。NexusAI 只在 pgvector 召回出来的候选池（最多 50 条）内统计——这是一个近似：IDF 只反映「这几个候选之间的分布」，而非全库分布。代价是区分度不如全局统计精确，收益是不用维护全局倒排索引。

### 4.3 归一化后与余弦距离融合

BM25 原始分数无上界，无法直接和范围 `[0,2]` 的余弦距离相减。NexusAI 把 BM25 分数按**候选池内最大值**归一化到 `[0,1]`，再融合：

```
score = 余弦距离 − KeywordRelevanceWeight × 归一化BM25
```

`KeywordRelevanceWeight = 0.15`，分数越低越靠前。归一化只改变幅度、不改变排序，因此单调且确定。

## 5. 一个算例

查询 `蓝雀告警`（bigram：`蓝雀`、`雀告`、`告警`），候选池 N=4，其中 3 个分块内容为 `蓝雀`，1 个为 `告警`：

- `df(蓝雀) = 3`，`df(告警) = 1`，`df(雀告) = 0`（未出现在任何分块，不参与计分）。
- `idf(蓝雀) = ln(1 + 1.5/3.5) ≈ 0.357`。
- `idf(告警) = ln(1 + 3.5/1.5) ≈ 1.204`。
- 各分块长度相同（都只有 1 个 bigram），`avgdl = 1`。

于是：

- `蓝雀` 分块得分 ≈ `0.357`。
- `告警` 分块得分 ≈ `1.204`。

归一化后 `告警` 分块为 `1.0`、`蓝雀` 分块约 `0.296`。结论：**罕见词 `告警` 的命中，远比常见词 `蓝雀` 更有说服力**——这正是 `TestBM25ScoresRewardsRareTerms` 验证的行为。

## 6. 边界与局限

- **局部 IDF 的近似性**：候选池很小（≤50）时，`df` 的统计噪声较大，IDF 只能反映候选内的相对罕见度。
- **bigram 对英文是近似词元**：`API service` 会被拆成 `AP`、`PI`、`se`、`er` 等字符 bigram，而非 `API`、`service` 两个词；对以中文为主的知识库影响有限，但若英文内容占比高，需要换成分词或混合词元策略。
- **纯字面信号**：BM25 不做语义判断，同义改写不会被识别——语义相关性由余弦距离负责，两者互补。
- **归一化依赖候选池**：池内最大值归一化意味着「绝对分数」只在同一批候选之间可比，跨查询不可比；对排序而言这没有影响。
